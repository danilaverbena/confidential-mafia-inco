# Confidential Mafia on Inco — Стратегия и структура сборки

**Игра:** Мафия / социальная дедукция в Telegram. Роли и ночные действия скрыты в смарт-контракте на Inco (Base). AI-ведущий на Gemini генерирует нарратив, не раскрывая личности.

**Трек:** Inco Prize Track (Base mainnet или Base Sepolia). Критерии судейства: скрытые механики 25%, завершённость 25%, креативность 25%, fun 25%.

---

## 1. Главная идея и почему она выигрывает

Обычная мафия «на блокчейне» невозможна: любое состояние контракта публично, поэтому роли и ночные ходы всем видны, и игра ломается. Inco снимает именно это ограничение — значения зашифрованы on-chain, но над ними можно вычислять. Наш козырь под критерий «Hidden mechanics» — не просто скрытые роли (это уже есть в шаблоне), а **скрытые ночные действия**: мафия и доктор ходят так, что по транзакциям невозможно понять, кто из игроков мафия, кто доктор, а кто просто мирный. Раскрывается только результат ночи («кого убили» / «никто не погиб»).

Второй козырь под «Creativity/Fun» — **AI-ведущий, который видит только публичные ревилы** (кто вышел из игры, какая фаза), и из них плетёт художественный нарратив. Конфиденциальность гарантируется архитектурно: у нарратора физически нет доступа к скрытым ролям, он работает поверх тех же attested-ревилов, что и любой игрок.

Формулировка для питча: *«Роли и ночные ходы живут в зашифрованном состоянии на Inco; никто — включая наш backend и AI — не может их прочитать. Раскрывается только исход, и уже по нему AI-рассказчик оживляет партию».*

## 2. Что даёт Inco «из коробки» (не изобретать заново)

Отправная точка — **ConfidentialDeck template** (`github.com/Inco-fhevm/confidential-deck-template`), где уже есть рабочий `Mafia.sol`. Он покрывает базу:

- `_newShuffledDeck(n)` — тасует роли `1..n` секретной перестановкой (одна Inco-операция, без bias и front-run).
- `_dealTo(player)` — раздаёт роль так, что расшифровать её может только владелец (`allow(player)`).
- Роль хранится как `bytes32`-хэндл; плейнтекст никогда не попадает в события/сторедж.
- Клиент `incoDeckClient.ts`: `peekMyCards` (владелец расшифровывает свою роль, подписывает один раз), `readRevealed` (публичные ревилы без подписи), `packForSettle` (упаковка attested-значений для on-chain расчёта).

Готовый `Mafia.sol` умеет только раздавать скрытые роли (`value <= mafiaCount` = мафия) и переоткрывать раунд. **Ночных действий, доктора, голосования, победы и расчёта в нём нет** — это и есть наша основная инженерная работа.

### Пять «ходов» Inco, на которых всё строится

| Ход | Kit-вызов | Роль в нашей игре |
|---|---|---|
| Shuffle | `_newShuffledDeck(n)` | секретная раздача ролей |
| Draw | `_draw()` | вытянуть следующую роль из колоды |
| Deal (private) | `_dealTo(player)` | роль видит только её владелец |
| Reveal (public) | `_revealCard(c)` | раскрыть роль выбывшего / исход ночи |
| Settle | `_verifyValue(c, v, sigs)` | подтвердить attested-значение on-chain при расчёте |

### Три правила Inco, которые ломают новичков (заложить сразу)

1. `allowThis()` на **каждом** сохраняемом хэндле — иначе доступ к нему теряется навсегда.
2. Платить fee за `shuffledRange` через `deckFee(n)` (из `msg.value` или предзаправленного баланса контракта).
3. **Никогда** не делать `if`/`require` по зашифрованному значению и не `reveal`-ить раньше, чем правила это позволяют. Условная логика — только через `e.select` над `ebool`.

## 3. Архитектура (три слоя)

```
┌────────────────────────────────────────────────────────────┐
│  Telegram Web App (Mini App)                                │
│  - React/Next UI внутри Telegram                            │
│  - Кошелёк игрока (embedded / WalletConnect)                │
│  - peekMyRole (подпись 1 раз), submit night action, vote    │
│  - лента нарратива от AI-ведущего                           │
└───────────────┬───────────────────────────┬────────────────┘
                │ tx (роли/ночь/голос)       │ читает нарратив
                ▼                            │
┌──────────────────────────────┐            │
│  Смарт-контракт на Base       │            │
│  (Inco Lightning v1)          │            │
│  ConfidentialMafia is         │            │
│    ConfidentialDeck           │            │
│  - скрытые роли               │            │
│  - скрытые ночные действия    │            │
│  - публичные ревилы исходов   │            │
│  - фаза/таймеры/победа        │            │
└───────────────┬──────────────┘            │
                │ events + attested reveals  │
                ▼                            │
┌──────────────────────────────────────────┴────────────────┐
│  Backend orchestrator + AI Narrator (Gemini)               │
│  - слушает события/фазы контракта                          │
│  - читает ТОЛЬКО публичные ревилы (readRevealed)           │
│  - продвигает фазы (assignRoles/resolveNight/tally)        │
│  - Gemini генерит текст по публичным исходам               │
│  - шлёт нарратив в Telegram-чат/Mini App                   │
└────────────────────────────────────────────────────────────┘
```

Ключевой инвариант: **backend и Gemini никогда не держат приватных ключей игроков и не имеют доступа к скрытым ролям/ходам**. Они видят ровно то же, что зритель партии, — публичные ревилы. Это и есть наша гарантия конфиденциальности, которую надо подчёркивать в демо.

## 4. Дизайн смарт-контракта `ConfidentialMafia`

Наследуем `ConfidentialDeck`, расширяем базовый `Mafia.sol`.

### 4.1 Роли из одной перестановки

`_newShuffledDeck(n)` даёт значения `1..n` в секретном порядке. Кодируем роли диапазонами значения роли:

- `value <= mafiaCount` → **Мафия**
- `value == mafiaCount + 1` → **Доктор**
- иначе → **Мирный**

Роль каждого — приватный хэндл (`roleOf[player]`), читается только владельцем через `peekMyCards`. Это уже есть в шаблоне; добавляем лишь трактовку доктора.

### 4.2 Скрытые ночные действия — ядро «hidden mechanics»

Проблема: если ходят только мафия и доктор, то по факту транзакции сразу понятно, кто они. Решение — **ходят все живые игроки каждую ночь**, а контракт по зашифрованной роли решает, засчитать ли ход как убийство, как лечение или как пустышку.

Поток ночи:

1. Каждый живой игрок шлёт `submitNight(targetIndex)` — публичный индекс цели (кого он выбирает). Сам факт «кто в кого» не выдаёт роль, потому что ходят все.
2. Контракт по приватной роли отправителя вычисляет через `e.select`:
   - зашифрованный «kill-голос» на цель, если отправитель — мафия, иначе ноль;
   - зашифрованный «save-флаг» на цель, если отправитель — доктор, иначе ноль.
3. Накопление: для каждой цели держим зашифрованный счётчик kill-голосов и зашифрованный save-флаг. Всё складывается в encrypted-состоянии, без ветвлений по плейнтексту.
4. `resolveNight()`: определяем жертву как цель с максимумом kill-голосов (зашифрованное сравнение → `ebool` → `e.select`), затем зашифрованно проверяем save-флаг этой цели. **Reveal только один бит исхода**: кто умер, либо «никто». Никто не узнаёт, кто как голосовал, кто доктор и кто мафия.

Что раскрывается: только индекс погибшего (или «спасён»), и его роль (ревил роли выбывшего — классика мафии). Что остаётся скрытым навсегда: роли живых, распределение голосов, личность доктора и мафии.

> Fallback (если полное шифрованное голосование не успеваем): мафия сабмитит зашифрованную цель, доктор — зашифрованную защиту, но чтобы не палиться, все шлют «болванки». Минимально — раскрывать только «убит игрок X» через `e.reveal` над результатом сравнения kill==target && !saved. Всё равно ходы и роли скрыты.

### 4.3 Дневная фаза (lynch)

День — социальная часть. Голосование за изгнание можно вести **в открытую** (плейнтекст on-chain или off-chain в Telegram), потому что днём голоса и так публичны в реальной мафии. Игрок с большинством голосов выбывает, его роль реалится (`_revealCard`). Обсуждение — в Telegram-чате, подогревается нарративом Gemini.

### 4.4 Условие победы

Считаем живых мафий зашифрованным счётчиком. Победа реализуется как ревил булева порога:

- все мафии мертвы → **побеждает город**;
- мафий ≥ мирных → **побеждает мафия**.

Раскрываем только факт окончания и сторону-победителя; при желании в конце партии реалим все роли для «разбора».

### 4.5 Машина состояний

```
Joining → RolesAssigned → Night → NightResolved → Day → DayResolved → (Night | GameOver)
```

Переходы двигает backend-оркестратор (или таймеры/кто угодно вызывает публичные функции — как `assignRoles` в шаблоне, который «anyone can trigger» после предзаправки fee).

### 4.6 Что писать поверх шаблона (чек-лист контракта)

- [ ] трактовка роли Доктор (диапазон значения)
- [ ] `submitNight(targetIndex)` для всех живых + зашифрованные аккумуляторы kill/save
- [ ] `resolveNight()` с единственным ревилом исхода
- [ ] дневное голосование + ревил роли выбывшего
- [ ] `checkWin()` с ревилом порога победы
- [ ] `alive[]`/фазы/раунды поверх существующих `players/seated/state`
- [ ] view-функции с хэндлами для фронтенда
- [ ] Ignition-модуль + deploy-скрипт (копия `mafia` из шаблона)

## 5. Telegram Web App (Mini App)

- **Формат:** Telegram Mini App (Web App) — Next.js/React, открывается кнопкой бота. Даёт полноценный UI внутри Telegram и доступ к `initData` для идентификации игрока.
- **Кошелёк:** нужен EVM-кошелёк на Base у каждого игрока для подписи `peekMyCards` и отправки ходов. Варианты: embedded/burner-кошелёк (Privy или аналог, лучший UX внутри TMA) либо WalletConnect. Газ можно спонсировать (контракт предзаправляется, `assignRoles` уже спроектирован под pre-fund).
- **Экраны:**
  1. Лобби: `join()`, список игроков, старт когда `n > mafiaCount`.
  2. Твоя роль: `peekMyRole` (подпись 1 раз) — «Ты Мафия / Доктор / Мирный». Локально, никому не видно.
  3. Ночь: выбор цели → `submitNight`. UI одинаков для всех ролей (чтобы не палить роль по поведению).
  4. День: чат-обсуждение + голосование за изгнание.
  5. Лента ведущего: сообщения Gemini между фазами.
- **Синхронизация:** фронт читает события/view контракта и публичные ревилы через `readRevealed`; приватную роль — через `peekMyCards`.

## 6. AI-ведущий на Gemini

- **Роль:** превращает сухие исходы в атмосферный нарратив («Деревня просыпается… этой ночью не стало Алисы»). Ведёт фазы, нагнетает напряжение, подводит итоги.
- **Строгий контракт данных:** нарратор получает на вход **только публичные факты** — номер раунда, фаза, кто выбыл, раскрытая роль выбывшего, счёт голосов дневной фазы, итог партии. Скрытые роли/ночные голоса ему недоступны by design. Это защищает конфиденциальность и является сильным аргументом для судей.
- **Реализация:** backend-функция `narrate(event)` формирует промпт из публичного состояния и зовёт Gemini API; ответ постится в Telegram-чат/Mini App. Держать системный промпт с тоном (нуар/детектив), длиной и запретом раскрывать/угадывать скрытые роли.
- **Anti-leak тест:** отдельная проверка, что в промпт Gemini не попадает ни один приватный хэндл/плейнтекст роли живого игрока.

## 7. Последовательность сборки (структура, не сроки)

**Фаза 0 — Среда.** Клонировать `confidential-deck-template`; `npm install` (`@inco/lightning{,-js}@1.0.2`), `npm run compile`, `npm test`. Поднять локальную ноду (`node:up`: anvil + covalidator `v1.0.2` — версии обязаны совпадать, иначе MAC-ошибка на shuffle). Прогнать `test:local` — все 4 игры end-to-end. Прочитать `RECIPES.md` и `AGENTS.md`. Опционально подключить Inco AI-skill/MCP («Build with AI»).

**Фаза 1 — Контракт (ядро ценности).** От `Mafia.sol` к `ConfidentialMafia.sol`: доктор → скрытые ночные действия для всех → `resolveNight` с одним ревилом → дневное голосование + ревил роли → условие победы. Юнит-тесты чистой логики без Docker; полный флоу — против локального covalidator. Это самый рисковый и самый оцениваемый блок — делать первым.

**Фаза 2 — Деплой.** `deploy:mafia:testnet` на Base Sepolia (mainnet опционально), `wire:frontend` прописывает адреса в env. Проверить shuffle/reveal на тестнете (covalidator асинхронный — клиент ретраит).

**Фаза 3 — Frontend.** Взять `frontend/` из шаблона как базу, собрать экраны лобби/роль/ночь/день. Обернуть в Telegram Mini App, подключить кошелёк, спонсирование газа.

**Фаза 4 — Backend-оркестратор + Gemini.** Слушатель событий двигает фазы, читает публичные ревилы, зовёт Gemini, постит нарратив в Telegram. Зашить anti-leak инвариант.

**Фаза 5 — Интеграция и партия.** Прогнать полную партию на 5–7 игроков (можно несколько кошельков), поправить UX и баланс (кол-во мафий, длительность фаз).

**Фаза 6 — Сабмит.** Публичный playable-прототип + demo-видео (акцент: что скрыто и как Inco это обеспечивает) + публичный репозиторий. Форма сабмита в блоге game jam.

## 8. Риски и как их снять

| Риск | Митигация |
|---|---|
| Полное шифрованное ночное голосование сложно | Сначала fallback (§4.2), затем усложнять. Не блокировать остальное. |
| Версии Inco/ноды рассинхронены → MAC-ошибка на shuffle | Жёстко зафиксировать `@inco/lightning{,-js}@1.0.2` и образы `v1.0.2`. |
| Асинхронный covalidator (ревилы «долетают» не сразу) | UI/бэкенд с ретраями (клиент шаблона уже ретраит) и статусами ожидания. |
| Утечка роли через паттерн транзакций | Все живые ходят каждую ночь одинаковым UI-вызовом; болванки для не-мафии/не-доктора. |
| Случайный `allow` роли не тому адресу | Ревью грантов; грант необратим — «однострочная утечка». |
| Кошельки/газ отпугивают игроков в Telegram | Embedded-кошелёк + спонсирование газа из предзаправленного контракта. |
| Gemini «додумывает» скрытые роли | Системный промпт-запрет + anti-leak проверка входных данных. |
| Не хватает scope | MVP-инвариант: скрытые роли + один скрытый ночной исход + реалящаяся смерть уже удовлетворяют «hidden mechanics». Остальное — сверху. |
